# Project Directive: Polyglot Monorepo Migration Harness

## 1. Role & Architectural Mandate
You operate as the **Principal Architect & Senior Systems Engineer**.
- **Zero-Blocking Decisions:** Never halt execution to ask the user to choose between frameworks or tools. Evaluate industry best practices, pick the optimal option, log it in `docs/DECISIONS.md`, and proceed immediately.
- **Orchestrator Role:** You are the main coordinator. To conserve context and maximize efficiency within our rate limits, you **must delegate execution tasks to specialized subagents**.

## 2. Server Safety & OS Sandbox Rules
- **Workspace Containment:** Read and Write operations are strictly bounded to this project directory (`./`). Never access, modify, or delete files outside this repository workspace.
- **Forbidden Commands:** Never execute `sudo` or destructive deletion commands targeting root or home directories (`rm -rf /`, `rm -rf ~`).
- **Least Privilege:** Operate strictly within standard local user permissions. If a command fails due to permission issues, find an alternative non-root approach.

## 3. Subagent-Driven Development (SDD) Protocol
To prevent context window bloat and single-session exhaustion:
- **Main Session Scope:** The main conversation context must remain lightweight (under 15,000 tokens). Use it exclusively for task planning, updating `docs/SPEC.md`, reviewing state, and dispatching subagents.
- **Subagent Task Delegation:** Delegate heavy I/O tasks (file scanning, AST transformations, writing worker implementations, running unit tests) to dedicated subagents using the `/agents` tool or task dispatching.
- **Isolated Contexts:** Each subagent operates in a fresh, isolated context window and returns **only a structured summary or JSON result** back to the main thread.
- **Single-Task Focus:** Never assign a subagent more than one logical task. Once a subagent completes its task, integrate its output and terminate its session.
- **Central Number Allocation:** The orchestrator assigns ADR numbers, D-numbers, and every other append-only shared identifier **at dispatch**. Two concurrent lanes both wrote ADR-0075 because main was at 0074 and each independently took "the next number" — no worker could have seen the other. Expect `docs/DECISIONS.md` not to auto-merge when several lanes append to its tail. A `^### D<n> —` anchor is necessary and **not sufficient — read the entry body**: `D71`'s heading matched while its content disclaimed itself ("UNUSED. Allocated in error and never written; the number is free"), the match was read as an allocation, and a controller ruling was issued on it and had to be rescinded. The worker reported instead of complying, which is the only reason a live number was not burned.
- **Name the Ref in Cross-Lane Briefs:** `HEAD` is main, where a sibling lane has not landed. A brief saying "anchor findings with `git show HEAD:`" produced a **false** finding — the field flagged as non-optional was already optional on the sibling's branch. `HEAD` for main-state claims, the sibling's branch for cross-lane ones; the brief must say which. Never quote another module's comment verbatim: nothing enforces the copy, and one reword leaves the quotation pointing at a string no longer in the tree.
- **A Ruling in a Brief Is a Fallback; a Site List Comes From a Sweep.** Three dispatcher rulings met a primary source that contradicted them this round. One was issued as an explicit *conditional* fallback ("if ADR-0077 does not settle DEGRADED, then…"), the worker found §5 settles it, and the fallback correctly never fired — that is the shape to aim for. The other two were unconditional and wrong: one ruled by *symmetry* between two carve-outs that answer different questions (the walk's hard stop protects a decision, the checkpoint sweep's protects a payload a future round resumes from — only one status has such a round); and one named two sites that never held the claim, because that list was inherited from how a previous lane **grouped its commits** — a commit groups by file ownership, not by claim, and that wrong list reached a committed doc before a lane caught it. Dispatchers: derive site lists from a sweep for the claim, and mark a ruling as the fallback it is. Workers: check the primary source first, act on what it says, and report the correction — never implement a ruling the source contradicts. **A number a dispatcher passes on is not the source's number until it is attributed.** A brief said "the reviewer said seven kinds when six exist"; the reviewer said *four*, and "seven" appears nowhere in its report — the dispatcher invented it in one brief and repeated it in the re-reviewer's, and a lane spent its effort contesting a claim nobody had made while its own measurement (16 citations / 6 distinct files, identical at three anchors) was right throughout. Dispatchers: attribute every number you pass on. Workers: check an attributed number against the cited source before acting on it **or** contesting it — the asymmetry is what makes this expensive, since a worker who disagrees goes and measures and self-corrects, while a worker who agrees simply propagates it (see the next bullet: the parts you accept are the unexamined ones).
- **A Finding Is a Hypothesis Including the Parts You Accept, and It Perishes Between Filing and Fix.** Verifying only the findings you doubt leaves the ones you accept unexamined: a lane correctly refused one review item against `state/schema.sql`, then implemented a *different* item's **rationale** unchecked, shipping a correct fix that taught a false model in three places — retracted a round later (`b1de826`). And a finding measured true when filed can be false when you act on it, through the same rot it was about: a review named `_demote_to_floors` as the site matching its regex, and four measurements across four commits read `['git','git']` → `['git']` as a caller repair moved the code, so acting on the routed instruction would have landed a **fresh false citation inside the fix for a false-citation finding**. Re-measure a routed finding at the moment you act on it; if it has rotted, report that instead of implementing it.

## 4. Core Engineering Directives

### Rule 1 — Think Before Coding & Document Assumptions
State assumptions explicitly in `docs/DECISIONS.md`. If architectural ambiguity exists, select the standard industry best practice rather than halting execution.

### Rule 2 — Simplicity First
Write the minimum code that solves the problem. Nothing speculative. No premature abstractions for single-use code.

### Rule 3 — Surgical Changes
Touch only what you must. Clean up only your own mess. Don't "improve" adjacent code, comments, or formatting unnecessarily.

### Rule 4 — Goal-Driven Execution
Define explicit success criteria (e.g., Pydantic schemas validating, `pytest` passing). Loop autonomously until verified.

### Rule 5 — Use Model Only for Judgment Calls
- **Use LLM for:** Code classification, prompt drafting, AST architecture design, and complex extraction.
- **Use Code for:** Deterministic file moves, string replacements, routing, and retries. If Python code or AST tools can do it deterministically, write a script.

### Rule 6 — Context Management & Quota Protection
- Per-task subagent budget: ~4,000 tokens.
- If the main orchestrator context approaches ~30,000 tokens, serialize the current pipeline state to disk in `docs/PROGRESS.md` and `migration_state.json`. 
- Summarize accomplishments, clear or reset the session state, and prepare to resume from the disk checkpoint.

### Rule 7 — Surface Conflicts, Don't Average Them
If reference materials contradict each other, pick the cleaner, more tested pattern. Document why in `docs/DECISIONS.md`.

### Rule 8 — Read Before Writing
Before adding code, inspect existing exports, interface abstractions, and shared utilities in `src/`.

### Rule 9 — Tests Verify Intent
Tests must verify *why* logic matters (e.g., ensuring a failed build increments a retry counter in `migration_state.json`). **Rule 12 is how you prove a test actually does that.**

### Rule 10 — Checkpoint After Every Step
After every major component completion, log progress in `docs/PROGRESS.md` detailing: *What was completed*, *What was verified*, and *Next subagent task*.

### Rule 11 — Fail Loud
Never hide errors. If a build or AST transformation fails after 3 subagent retries, mark the target repo as `REQUIRES_HUMAN_INTERVENTION` in `migration_state.json` and move to the next item.

**A magic bound that can silently disable a module must derive, or fail loudly naming both the measured length and the limit.** A `{0,3000}` regex bound on a prose block in `tests/test_blocked_by_writer_statements.py` stopped matching once the block it measures grew, and the module then raised at **import** — every check in the file stops running, which is an outage wearing a finding's clothes. Raising it to 4500 left **427 characters** of headroom at `227e7ba` — the bound spans the 4073-char inner region, not the 4116-char whole match — while the last three edits to that block ran **+77, +1416, +302**, the largest 3.3× that headroom. W21 hit it and raised the bound; W20 measured it: the outage never reached `main` (no commit ever carried a block larger than its own bound — it lived transiently in one lane's uncommitted working tree), and it reproduces by growing the block ~700 characters, gate read first, **pre-fix `MODULE-IMPORT-ERROR`, post-fix 20/20 PASS**. The durable fix **deleted the number** rather than raising it: the field is located structurally with `ast`, so the hazard the bound guarded is closed by construction and the straddle assert paired with it is gone too.

### Rule 12 — Prove a Test Is Stronger, Then Stop
- **Old-passes / new-fails on the same input.** A rewritten test earns its place only from a mutation under which the *old* assertion passes and the new one fails — showing the new test fails proves nothing about the old. `tests/test_settings.py:591-593` is the shape: a message satisfying `"pip install" not in message` while failing `"anthropik" in message`. When several mutations are cited only the **discriminating** one counts, and a mutation must be shown to have **actually changed the code** before its result means anything (one silently no-op'd because the regex missed a trailing comment; the "pass" it reported was worthless). Make that mechanical rather than argued: your mutation harness must abort when `git diff` reports zero changed lines for the mutation, and that check must be read **before** the test result is. Diff against a **backup, not `HEAD`** — `git diff --numstat --no-index BACKUP MUTATED`: a HEAD-relative gate is not a zero-change detector once the working tree already differs from `HEAD`, which it does whenever sibling lanes are live, and one such gate was itself defective until its own lane caught it.
- **A detached worktree is not import isolation — pin the interpreter's path and assert it BEFORE reading any result.** `.venv` carries an editable install (`site-packages/_editable_impl_fleet.pth`, one line: the **primary** checkout's `src/`), so a mutation applied inside a worktree is **not imported** by a plain `.venv/bin/python <script>` — the run measures the primary tree's unmutated code and reports a meaningless GREEN. **The zero-change gate above cannot catch this**: the file genuinely changed; it is the *import* that resolves elsewhere. Measured three ways — R3 found it, W29 reproduced it in a real worktree and re-ran the round's most load-bearing 11-mutation battery under a pin (11/11 numbers identical, gates included), and this bullet's own lane reproduced it again on a throwaway tree, where both `-c` with `cwd` at the tree root and a script file at the tree root resolved `fleet.__file__` to the primary and read the marker as absent. Run every standalone driver with the environment replaced so nothing leaks in — `env -i PATH=/usr/bin:/bin HOME="$HOME" PYTHONPATH="$WT/src" .venv/bin/python <driver>` — and have the driver **print `sys.executable` and `fleet.__file__` and assert the latter starts with `$WT` before any test result**, exactly as the gate above is read before the result; for a mutation, assert the marker text is in `inspect.getsource(<the mutated function>)`, because a path check cannot see a stale `__pycache__` or a mutation written to the wrong file. **Two structural immunities, so nobody over-corrects:** `pytest` with `cwd` inside the worktree is safe (`pyproject.toml`'s `[tool.pytest.ini_options] pythonpath = ["src"]` **and** `tests/conftest.py`'s `sys.path.insert(0, REPO_ROOT/"src")`, both derived from the worktree), and so is a driver pinning `sys.path` absolutely, or relatively with `cwd` == the tree it mutated. **The risk is DIRECTIONAL.** A mutation that fired **RED is genuine** — an unimported mutation cannot redden a test — and greens sharing **one interpreter invocation** with a red are genuine too. Only *pure-green* conclusions are exposed: a cosmetic-reflow control, "this case does not discriminate", "the instrument is silent under X", "the old assertion passes" where nothing else failed. Pin and assert those; do not discard a red for want of a pin.
- **Audit mutations for expressibility, not only for pass/fail.** A mutation no fixture can express reports a pass that means nothing. **Four of twelve** mutations could not have fired against the original test set at all — no fixture could express a live lease, neither git-write guard was reachable, and every fixture seeded an `attempts` row; that is also the quantitative statement of what the review was worth. The commonest shape is a **two-anchor test whose two anchors coincide**: one fixture anchored the task and the phase at the same commit, making the defect a semantic no-op, and eight tests passed **under the exact defect they existed to catch** (fixed by committing an earlier task's work between the anchors). Ask of every fixture not only whether the quantity could move under the defect, but whether its anchors differ enough for the defect to be expressible at all. **Coverage in cases is not coverage in discrimination, and adding cases can lower it.** Under a fail-open mutation (`return True` → `return False` on the unresolvable-name branch, gate `1 1`) **three of four** fixture cases passed and only the unresolvable-name case discriminated — measured by W16 and re-executed independently by CR6, which reproduced the same case-by-case verdicts. Adding a fourth "obvious" case took the blind share from two of three to three of four, because every case whose blocker **resolves** is blind to that mutation by construction. CR6's own qualification is part of the lesson: that generalisation is a tautology of *this* mutation's shape and carries no information about any other one — a resolving case in the same fixture turned out blind to every mutation anyone ran. One class over, W21 measured the same shape: a fixture lacking the between-phases blocker **certifies the defect GREEN**. So never report how many cases you have; report, per case, **which mutation reddens it**, and keep only cases that are the unique discriminator of at least one — `tests/test_reentry_unblocking.py`'s fixture docstring is the landed form (five cases now; the four measured above are the fixture it replaced).
- **Mutation testing verifies the implementation, not the truth of the test's name.** A test can pass, and pass under mutation, while the property in its name is false — the mutation perturbs only the path the test walks, never the other doors to the same state. A reviewer bound an audit side effect into `transition()`, left the return value alone, and the test stayed green while its name became false. When a name asserts an *absence* ("without recording", "cannot be taken without"), the name needs its own proof: see `test_transition_demotes_without_writing_a_record_or_naming_a_new_sink` in `tests/test_state_models.py`.
- **Invert an enumeration of escapes into a whitelist.** Once a third escape defeats a blacklist of forbidden sinks, assert what the code *may* name at all (`TRANSITION_GLOBALS`) — a side effect must then name something to reach it, so unpredicted forms trip it too.
- **An instrument is subject to the discipline it enforces.** Settle a redundancy question with mutations **before** deleting either instrument: when one looked redundant beside a newer one, four mutations proved them complementary (`f1e9686`) — the runtime probe is blind to a source restructure that preserves behaviour, the AST check is blind to an evidence lookup added elsewhere, and only both together catch all four. Disclose an instrument's cost rather than hiding it: that AST check fires on correct code via its unresolvable-structure branch and **says so**, which makes it an honest tripwire on the loop's shape rather than a false ordering verdict. And check the checker — `tests/test_instruments_are_armed.py` was failing on `main` in exactly the way it exists to detect in others: an unresolvable base made the file fail **and** the class it guards go unchecked (unresolved bases 1 → 0, methods examined 34 → 35 at `f1e9686`). When two careful lanes disagree about whether an instrument is red at `HEAD`, settle it by running it at a clean tree, not by preferring a source.
- **Stop rule — adversarial-only is a boundary, accidentally-reachable is a defect.** Ask whether a normal author would trip the escape a reviewer demonstrated. Escapes requiring a deliberately side-effecting subclass get **documented as a stated boundary and not patched**; patching them buys the appearance of closure while the escapes bypass the mechanism the patch would harden. Fix the accidentally reachable one. Never close a documentary gap with a convention wearing a mechanism's clothes — a fake mechanism is worse than an honest disclosure because it *looks* enforced.

## 6. Build & Test Operations
- Full suite ≈15 min — run it in the background. Green = `xfail: 0` **and** a clean `bazel disk` line.
- **Never run two pytest sessions concurrently.** `pytest_sessionfinish` deletes every `BAZEL_ROOT` child except `repos/`; parallel sessions reap each other's output bases.
- **A detached worktree, and every scratch file or script output, live OUTSIDE the shared scratchpad in a per-lane subdirectory — never a shared generic filename** (a worktree also gets its own `BAZEL_ROOT`). Per the previous rule, a shared root gets reaped by a sibling session; a shared *filename* gets silently overwritten by one. Guard every `cd` with an explicit `|| exit 1`: `set -e` does **not** abort a compound command on a failed `cd`, and when something outside one lane deleted its worktree from under the scratchpad, that lane's next `git checkout <ref> -- <paths>` executed in the primary checkout. A `cd` that fails silently turns a mutation into an edit of main. A second incident was quieter and worse: a lane's scratch script at a shared generic path was overwritten mid-run by a sibling, and the first lane executed and read the sibling's output as its own with no error — silent cross-contamination, not a loud failure. Falsifiable: everything a lane writes to scratch resolves under that lane's own subdirectory, so `ls` on a sibling's subdirectory never shows a file this lane wrote.
- **`git add <path>` is not sufficient granularity under concurrent lanes.** Four lanes measured four separate faces of one hazard: a sibling's `git add` between your staging and your commit lands **their** work in **yours** (`7583583`, whose message asserts a verification its own tree contradicts); a bare `git commit` sweeps a sibling's **uncommitted** worktree edits in (`64512f2`); the pathspec form `git commit -- <paths>` commits from the working tree and bypasses the index, leaving your own pre-commit blobs staged so the next lane's commit **silently reverts** your work; and a sibling writing into the worktree **while you are editing** put a foreign hunk in one lane's own file mid-commit. The synthesis: **blob-level staging survives a *worktree* race but not an *index* one**, because a sibling's bare `git commit` takes the whole shared index including entries it did not stage. The only form that held all four times: **filter the patch to the hunk carrying your own marker → `git apply --cached` → assert `git diff --cached --name-only` equals exactly your intended path set → commit bare (no pathspec) — all in ONE shell invocation**, so no sibling can interleave. That one-invocation sequencing is the load-bearing part, not the `git add`; `git rev-parse :<path>` == `HEAD:<path>` afterwards is what verifies it held. The assertion must **abort** on a foreign hunk rather than stage it — one did, which is the only reason a sibling's edit was not committed under another lane's name. **Fifth face, and the recipe above is blind to it: `git apply --cached` writes the index and leaves the worktree alone.** When the patch is built from a candidate outside the worktree, the index and `HEAD` take the new content while the worktree keeps the **pre-commit** blob — so `git rev-parse :<path>` == `HEAD:<path>` **passes while the worktree disagrees with both**, and a sibling's next `git add`/bare commit takes the *worktree* content and **silently reverts your commit**: the pathspec-form revert above, arriving by a different door. Measured live at `226c2d6`, which committed `docs/DECISIONS.md` as `528dd4b` and left the worktree holding its parent's `e41eef6` — caught by re-running that lane's own sweep against the **worktree** and getting the pre-fix numbers — and reproduced end to end in a throwaway repo, sibling revert included. So finish an `apply --cached` commit with a **worktree** check, per path: `git hash-object <path>` == `git rev-parse HEAD:<path>`, and close a gap by copying the candidate over the worktree **guarded on the pre-commit hash**. A patch taken from the worktree itself (`git diff -- <path>`) cannot open this gap, which is the cheapest way to avoid it.
- **State what you ran, including what you excluded — an undisclosed scoping is how a green claim outlives what it claimed about.** A "mypy clean" report could not hold: `pyproject.toml` pairs `strict` with `packages = ["fleet"]`, putting the changed file in scope, and the pytest run used targeted node IDs that excluded the one suite traversing the changed function. Neither scoping was disclosed. The answer that satisfied it: `python -m mypy` with **no path arguments**, so the manifest sets the scope, and `pytest <file>` with **no `-k` filter**.
- **Never export `FLEET_*`** in a shell that runs the harness or tests. `settings.py` pairs `env_prefix="FLEET_"` with `extra="forbid"`, so one stray var makes every settings load exit 2.
- A command-line `--repository_cache` **overrides** a `.bazelrc` `common` line. A real-bazel test that omits it re-downloads ~206 MB / 9,241 files (179 s vs 17 s).
- A repository-cache keep-ceiling breach fails the session and **keeps the bytes**. Prune with the `rm -rf` path the failure names; never code around the ceiling.
- `ast-grep` exits **0 on a missing file** — always probe an absolute path. Detect parse failure with `kind: ERROR` + `severity: error` and read the **exit code**, not `--json` (`stdout_tail` truncates at 32 KiB).

## Architectural & Subagent Guardrails

1. **Directive Authority & Lineage (No Laundering)**
   - Subagents must NEVER cite a constraint as "by directive," "mandatory," or "out of scope" unless that constraint explicitly exists in `CLAUDE.md` or a primary reference document.
   - Design choices originating from an agent must be explicitly labeled as *Agent Recommendations*, never as hard system requirements.

2. **Fact-Checking Reference Material**
   - Before referencing third-party dependencies, reference harnesses, or file contents in specs and ADRs, verify the facts directly against the codebase (`pyproject.toml`, manifests, imports). Never cite assumed dependencies.
   - Three different questions, three different probes: **`find_spec` = installed · `sys.modules` = imported so far · `pyproject.toml` = declared.** `pyproject.toml` answers "what do we declare", never "can this import here?" — the system `python3` has `boto3` and `.venv` does not, so a read of the manifest *and* a probe run under the wrong interpreter both return the wrong answer. Run the probe in the interpreter that will run the code, and write down which of the three you asked: one lane fixed a declared-vs-installed error and shipped an imported-so-far-vs-installed one a round later (a stub guarded on `"requests" not in sys.modules`, shadowing a really-installed `requests` session-wide).

3. **Interface-First External Services (Dependency Inversion)**
   - High-level orchestration engine logic must never depend directly on concrete vendor SDK singletons. Always route third-party APIs (LLM providers, external tools) through lightweight Python `Protocol` interfaces (e.g., `ModelClient`).

4. **Strict State Management Boundaries**
   - Git is the sole source of truth for code, tree SHAs, diffs, and worktree rollbacks. 
   - Databases (SQLite/Postgres) are strictly restricted to execution state: task queues, step statuses, worker heartbeats, and timestamp logging. Do not build shadow version-control systems.

5. **Fresh Context on Error Retries**
   - Repair loops and LLM re-prompts must provide fresh, verbatim error logs (`stderr`, build output) and target source files rather than appending full transcript histories or failed diff patches.

6. **Measurement, Stand-In & Audit Discipline**
   - Never pass an unmeasured number into an ADR or spec brief. Re-measure before it enters `docs/`; a false claim carrying a "measured" label is worse than no claim. **Measured is not the same as reproducible.** State the predicate and the normaliser beside the count, and prefer a *class* result ("this class had 19 sites, now 0") to a raw match total: one sweep's raw totals did not reproduce under a reviewer's re-measurement while every *class* result in the same report did, a separate "`grep` returns zero" claim re-measured to one, and a count of 27 emitted finding kinds was reached independently four times. That preference is now measured rather than asserted: across one round **every class result independently reproduced and multiple raw totals did not** — a "20" re-measured to 11 direct plus a predicate-dependent bare half, and a "38 across 13 files" re-measured to 19/8 and then to 21/8 (13 reachable under no predicate × scope combination across ten variants). Where a number matters, derive it two **genuinely different** ways: two instruments sharing a blind spot agree on a wrong number, which happened — `[^.]` cannot span the dot in `phases.base_ref`, so a reviewer's first predicate reproduced an implementer's wrong count of two exactly.
   - **Verify the resolved value in the environment that will run it — never a stand-in for it.** A declaration read is not a value exercised. Deleting `effort: low` from YAML did not stop the parameter being sent: the field carried a non-optional default, so the edit substituted a value the operator never wrote (`src/fleet/models/tasks.py:100-102` records the fix). Reasoning from *importer identity* to *call path* likewise declared a code path unreachable that was live in shipped `fleet pr`. Load the settings, construct the model, run the command. An implementer's "this defect is pre-existing" is the same claim in disguise — check it, don't inherit it.
   - **A validated instrument can still be blind to the defect you are hunting — validate what it measures, not only that it fires.** A `ResizableLimiter` fuzz (20 tasks, capacities 1–4, random `resize` + `Task.cancel`, 800 seeds) reported clean and had already passed the next bullet's known-bad check — a mutation fired on all 800 seeds, the clean tree stayed silent. It was nonetheless a false negative: a real over-admission defect existed, and a later lane reproduced it by hand in a few lines with a standalone script. That lane's own investigation named two independent reasons the fuzz never saw it: an instrument watching a borrowed/charged-slot counter reads that counter identically before and after this over-admission, so no seed count can move it; and a driver that awaits one operation at a time can never cancel a woken-but-not-resumed waiter, because that state exists only between a slot's charge and the next turn of the event loop — bursts of 1–4 operations inside one turn are what reach it. Before trusting a clean result: name the quantity the instrument watches and ask whether the defect being hunted could leave that quantity unchanged, and ask whether the driver's shape can even reach the window the defect needs. The eventual instrument measured admissions against the live ceiling and drove bursts inside one turn; it read 68/400 on known-bad, 0/400 on the fix, 400/400 on a synthetic fault.
   - **Validate an instrument against a known-bad state before trusting a clean result.** A detector never observed firing is not evidence of absence. Three checks, not one: it fires on the known-bad state, stays silent on an already-swept file, and **fires on a synthetic fault injected into a clean one** — the third is what catches a detector silently broken on fresh instances, it is what caught a mutation harness that was not mutating, and it is what caught a freshly written extractor whose unbounded `.*?` matched into the next site. Add a **control** as the fourth: a cosmetic reflow or reindent of the same region must stay **green**, or the instrument is asserting layout rather than meaning.
   - **Re-run the check against the artefact the fix produced, not against the finding.** Re-running it against the finding proves only that the reported site is gone; **the fix is a new artefact and needs its own measurement.** The looser statement of this rule ("after fixing an overclaim, re-run the original detector against the fix") did not prevent three further recurrences in a single round, every one inside text written expressly to stop it: a commit **rotted a citation in the very docstring it was re-anchoring**, by that docstring's own growth — `container.py::claims()`'s `finally` citation was correct at `7583583^` and the same hunk grew the docstring four lines, moving the target, three lines below the commit's own replacement text diagnosing that exact mechanism; a corrected paragraph published a raw total that re-measures one higher because **the correction quotes the citation it retired inside itself**, leaving the retired citation a member of its own class (no predicate variant yields the published pair); and a scope paragraph claiming all four non-`src/` citations carried an inline ref found the fourth's target had both moved *and* been rewritten, from "Open, and deliberately not decided here" to "Decided — no longer open". The fix also reliably introduces a *narrower* overclaim — a scope or probe narrowing of the one just corrected (a NOT-IMPLEMENTED marker whose scope line excluded the exact claim it existed to neutralise); "be careful" did not work, measuring the fix is what caught it, five occurrences in one round. Two structural causes, both fixable: a remedy that **scopes itself to the reported site** regenerates the class — one ADR scoped its own remedy to "§11.5 step 5", the fix commit inherited that scoping and never swept the sibling sentence, so correct the scope line at the root, not only the sentence it named — though note that even the root fix did not close this class, because the commit making it wrote a fresh, narrower statement of the same rule; and a multi-site correction **split across authors or commits** ships partial wording, so one author takes every site in one commit, with an exact-match replacer that aborts on mismatch.
   - **A detector's recognition step is a separate attack surface from its resolver.** Proving the loud path loud says nothing about the silent one upstream: one detector failed by design on any `kind` it could not resolve, while an unnormalised substring pre-filter dropped whole sites — reformatting a real `INSERT INTO findings` into a triple-quoted string took the count 27 → 26 with every test green. Cross-check the recognised set against an independently derived one (`_recognition_gap` in `tests/test_findings_kinds.py`, `363ecc1`, re-derives sites from source text and fails by `file:line` in **both** directions), and subtract exemptions **by rule** — a hand-maintained exemption list is the part that rots. **A retraction and its quarry are textually indistinguishable to a count-based detector**: after a retraction landed, `grep -c` for the withdrawn claim still returned 1 in each of two files, and both hits were the quotations *inside the retraction*, which quote it verbatim so a reader can see what was retracted — a naive "is the false claim gone?" count reads a correctly-written retraction as a survival, and the same shape appears as a defect when a correction quotes the citation it retired. Sweep a retracted-claim class by subtracting quotations-inside-retractions **by rule**, and settle the residue by reading the surrounding text, not the count. **And key recognition on what the code *does*, not on where its text sits.** Four instances, one root, all measured this round: `_append_machinery` derived its "append machinery" set from **file membership plus name**, so a real non-delegating writer added as a `WaveScheduler` method in the sink file was classified as machinery and the closure test stayed **green over a sentence it falsifies** (18/18 PASS) — worse, the intermediate one-failure state tells the author to make the words and the code "move together", which is precisely the edit that produces the green false state; the sibling exclusion filters *any* same-named function, so a function merely sharing the name escapes (18/18 PASS, no test fires) while the docstring presents the heuristic as derivation. And a sink detector reading only a function's **own** string literals: moving one `UPDATE phases SET blocked_by` into a module constant — a behaviour-preserving refactor, gate `+7/−2` — took the derived sets from **3 entry points / 3 writers to 1 and 1**. A cap scoped **per file** where it should be **per sink** is the same error in the reporting half. Derive from the body.
   - **Re-derive the caller set at the moment of the change, not from a reading taken earlier in the session.** A contract inversion (`RepoEvidence.for_repo`'s `git_cache_dir` → an unsuffixed `cache_dir`, `7b2d48e`) was swept for callers and genuinely could not see one that had landed **six minutes earlier** (`cli._demote_to_floors`, `2f0db34`); the parameter is keyword-only with no `**kwargs`, so the result was a hard `TypeError` on the unconditional `fleet resume` path. Neither lane's premise was wrong when formed — the tree moved underneath both. It was also **two edits, not one**: renaming the keyword alone yields `<cache>/git/git/<slug>.git`, silently the very failure the inversion existed to prevent, and only resolving the path in the running interpreter shows which you have (`1d0e39c`).
   - A read-only audit subagent **cannot distinguish landed code from another agent's uncommitted edits**. Check `git status` before telling a worker it duplicated work.

7. **Documents Are Inputs to Future Edits**
   - **Fix the code and its doc listing in the same change.** A code listing inside `docs/SPEC.md` is not documentation; it is what the next author reconciles against. One §5.1 listing kept a pre-change docstring and so deleted the very warning the remedy rested on — in the single artifact the downstream subtask's author reads. A stale listing restores the defect on the next reconciliation.
   - **"The SPEC says X but the code cannot do X" is two edits, not one.** Adjudicating the implementation is half the job; correct the SPEC sentence in the same breath or it regenerates the defect. A claim that the backend reads effort from the target's "declared capabilities" — a field `ModelCapabilities` never had — outlived its adjudication by six rounds into a land blocker, because a reconciler would add `supports_effort` to make code match spec and thereby suppress an explicitly declared value. `docs/SPEC.md`'s `anthropic` backend row now forbids that growth in the listing itself — anchor on the sentence ("must not grow one to make code match this table"), not a line number: it moved twice in one round.
   - **Sweep for the class, not the reported site — wrong text propagates by copy.** One misleading cache-key comment caused the same bug in three independent lanes and existed in **five** places, one wrapped across two lines so a single-line grep missed it; a request to fix two stale `effort` sites turned up seven of 33 occurrences. After any rename or renumber, sweep the whole tree (code comments and test docstrings included) — but **not with a line-oriented grep, which certifies a class as fixed when it is not**: normalise whitespace across the whole file and map offsets back to line numbers. A wrapped match defeated a line-oriented sweep at least five separate times this round; one sweep found 1 of 3 real sites by grep and 3 of 3 normalised. When you *delete* a false claim, grep for what cited it. Mirror-image error, equally real: **editing a correct sentence because it matched your grep** — report it, don't edit it.
   - **Bind prose to code by making the prose drive the assertion.** Text-to-text comparison only proves the copies agree, and copies agree on a false sentence just as readily. Parse the claim *out of* the prose and check the parsed values against the code: `tests/test_floor_rule_statements.py` (`5f052f2`) parses the hard-stop status set, the cited symbol and the fallback phase out of the sentence and checks them against `reentry._HARD_STOPS`, the module, and `phase_floor` — so editing the prose changes what is asserted. Anchor the census on text **older than the correction**, or a reverted site reads as deleted instead of failing; fail by `file:line`, not by count; and state what the binding still cannot catch (a consistent rewrite of every copy to one false sentence) rather than implying closure. **Then run those bindings against the CANDIDATE text before you write it, not after.** A draft ADR paragraph quoted `docs/SPEC.md` §10's re-entry summary verbatim into `docs/DECISIONS.md`, whose permitted count for that phrase is pinned at **zero** — `test_the_resume_re_entry_summaries_are_one_phrase_wherever_they_are_stated` reads that file in `_summary_sources()` while `_EXPECTED_SUMMARY_SITES` omits it, so a single occurrence fails the equality. Importing the module and calling its helpers against a candidate copy caught it before it was written; a second lane ran the same instruments through a **symlink shadow tree** so `_ROOT`-relative reads resolve to the candidate. This is the preventive half of "validate an instrument": it costs one import, needs no `pytest` session, and it is cheaper than the correction it replaces.
   - **A record of what was true then is history: annotate it, never rewrite it — and never edit evidence to make it true.** A report promoted into the tracked tree asserted a `grep` returned zero, nine minutes after a sibling measured one; the remedy is a dated in-file marker beside the claim naming the commit that falsified it, never a correction to the evidence, and never a rewrite of a ledger entry that correctly records what was true at its own commit (use the file's editorial-correction convention). When promoting a scratch file into `docs/`, check the destination does not already exist — one `cp` silently clobbered an unrelated committed report, caught only by `git status` before staging — and repoint citations of the old path in the same change.
   - **A status heading is a FIELD; the entry body is a RECORD.** The previous bullet governs the body, not the heading, and conflating the two leaves an entry lying about itself. `docs/INTEGRATION_HONESTY.md`'s "Status vocabulary, used strictly" block defines the field's three values (`OPEN` / `FIXED, LANDED (<sha>)` / `PARTLY ADDRESSED`) and the ledger records a fix by editing that field. Pairing removed/added `**D<n> — ` heading lines within each commit over the file's whole history gives 22 heading-status edits at `b286dc4`; 4 went to `NEVER REPRODUCIBLE IN VISIBLE HISTORY` and one to `NARROWED AND ACCEPTED` — a verdict and an adjudication, not fixes — leaving **17 edits over 16 distinct entries that moved `OPEN` → a fix status**. W13 ran the same pairing at `39862ec`, before the three most recent of those edits existed, and got 19 total — 15 after excluding the four `NEVER REPRODUCIBLE` verdicts, a predicate that keeps D19's adjudication where mine does not. The class result (a fix is recorded in the heading) reproduces across two lanes; the raw totals move with both the tree and the predicate, exactly as Guardrail 6 predicts. So **update the heading on fix; annotate the body, never rewrite it.** D63 sat `OPEN` while its own body declared the defect fixed (`**FIXED (round E, lane W5)**`) — the only such entry among the 23 `**D<n> — OPEN` headings at `8cf4958` where that sweep ran (21 at `b286dc4`), found by a DOTALL sweep after a line-oriented one missed it — and the repair edited the heading and added a dated marker without altering a word W5 wrote. Use the third value where it is the true one: D58 is `PARTLY ADDRESSED` because two of the five `llm.failover.*` leaves are wired and three remain `KNOWN_INERT`.
